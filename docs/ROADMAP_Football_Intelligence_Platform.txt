GOLDEN RULES (read them again at the start of every week)
---------------------------------------------------------
1. A small finished project beats a huge unfinished one. MVP first.
2. Never train a model inside Django. Train in ml/, save .joblib, load in Django.
3. No data leakage: a match feature may only use data from BEFORE that match.
4. Always split by time (walk-forward), never random.
5. Always compare to baselines. A model without a baseline means nothing.
6. Commit to Git at least once per working day, with a clear message.
7. Be honest about accuracy: 50-55% on 1/X/2 is already a good result.
8. Notebooks for experiments, .py scripts for final code.

PHASE 3 - FEATURE ENGINEERING FOR THE MATCH MODEL   (Week 3)
==============================================================================
GOAL: a leak-free feature table, one row per match, ready for training.
Files: ml/features.py + notebooks/02_match_model.ipynb

CONCEPT: process matches in chronological order. For each match, compute
features using ONLY matches with date < current match date.

TASKS
[ ] [M] Target variable: result in {H, D, A} (encode 0/1/2 consistently and
        save the mapping).
[ ] [M] Elo rating per team:
          expected_home = 1 / (1 + 10 ** ((elo_away - (elo_home + HOME_ADV)) / 400))
          update: elo += K * (actual - expected)   (K ~ 20, HOME_ADV ~ 60-100)
          Start every team at 1500; for promoted teams use a lower start value
          or the average of relegated teams. Store elo_home, elo_away, elo_diff
          BEFORE the update.
[ ] [M] Rolling form features (last 5 and last 10 matches, per team, shifted so
        the current match is excluded): points per game, goals for, goals
        against, goal difference, win rate.
[ ] [M] Home form (last 5 home matches) and away form (last 5 away matches).
[ ] [M] Rest days since previous match.
[ ] [M] Head-to-head features: over the last N meetings (use all 7 seasons):
        home wins, draws, away wins, average goal difference.
[ ] [S] Advanced stats (Understat): rolling xG for / xG against (last 5).
        Handle seasons without Understat.
[ ] [S] Squad-quality features from player data: average rolling points of the
        team's top players before the match, minutes continuity, injuries
        proxy (players with 0 minutes recently).
[ ] [S] Season context: gameweek number, early-season flag (few matches played).
[ ] [C] Bookmaker implied probabilities (normalized 1/odds). Keep them in a
        SEPARATE feature set: main model WITHOUT odds, benchmark WITH odds.
[ ] [M] Cold start rule: first matches of a season/team have little history ->
        use priors (league average / Elo start) and add a "matches_played"
        feature, or drop the first 3-5 gameweeks of 2020-21 from training.
[ ] [M] LEAKAGE TEST (pytest): for random matches, recompute features using
        only earlier matches and assert equality; assert no column comes from
        the match itself (goals, shots, xG of that match).
[ ] [M] Save the final table: data/processed/match_features.csv and the ordered
        list of feature names in ml/artifacts/match_features.json.

DELIVERABLES: features.py, match_features.csv, leakage test.
DONE WHEN: the table has no NaN issue you did not decide on, and the leakage
test passes.

WALK-FORWARD FOLDS
  Fold 1: train 2020-21..2021-22 -> test 2022-23
  Fold 2: train 2020-21..2022-23 -> test 2023-24
  Fold 3: train 2020-21..2023-24 -> test 2024-25
  Fold 4: train 2020-21..2024-25 -> test 2025-26
  Extra : played matches of 2026-27 = final out-of-sample check
  (Inside a fold, if you tune hyperparameters, use TimeSeriesSplit on the
   TRAIN part only - never on the test season.)

TASKS
